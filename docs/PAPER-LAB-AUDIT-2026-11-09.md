## 为什么不显示“真实 AI 思维链”

Agent 的可观测运行过程包括任务接收、工具开始/结束、模型输出状态、等待授权、失败或完成。这些可以由宿主原生 hooks、MCP 事件、审计事件或只读日志提供。

模型隐藏的内部推理文本通常既不可通过这些接口得到，也不应由前端凭空生成。本轮使用 `OBSERVED EXECUTION` 字样；工具分布条形图对应的也是**已缓存事件类型计数**，不借助随机数画成“脑内活动”。跨宿主依旧保留 `host-native / derived / simulated` 和 `confirmed / inferred / unverified`。

参考：[OpenTelemetry Semantic Conventions for Generative AI](https://opentelemetry.io/docs/specs/semconv/gen-ai/gen-ai-spans/)。

## 后续验收门槛

1. **原版视觉 A/B**：同分辨率同光效截图，并人工查看 30 秒动态流。核验环位、亮度层次、右侧光束、弧形刻度、底部面板密度、细字体而非模糊不可读。目标是风格一致，不复制原版虚构的 Paper/Method 业务数值。
2. **真事件回放**：使用 DSH `host-native/confirmed` 的真实事件验证面板时间/状态/工具；其它宿主仅在证据齐备后提级。跨会话选取之后不得混淆来源。
3. **离线与缺字段**：SSE 断线应保留过期说明；没有 token/context 指标显示 `—`；不能把 0 条错误事件直接宣称全局 PASS。
4. **模拟标签**：URL `?demo=1` 时全局及底部必须清晰显示 SIMULATED；GitHub Pages 不能冒充真实运行数据。
5. **响应式与可用性**：1440×900、1600×900、1920×1080、1080p 缩放、小屏、紧凑窗口测试；按钮键盘可达、预设切换可逆、reduced-motion 有效。
6. **性能预算**：真实 Windows 设备连续运行 5–30 分钟，测帧率、浏览器 CPU/内存、长任务推送积压，必要时退回低粒子数；不得以单张静态图证明性能。
7. **Obsidian 数据边界**：导入 JSON 的字段白名单、超大文件拒绝、隐私、安全边界测试；明确导入不是实时同步。

## 建议工程阶段

- P0：完整回归测试与真实桌面截图；修复可读性/渲染问题，保存前后对比图。
- P1：从独立宿主 adapter 提升事件语义保真度（正确开始、结束、耗时、错误、置信度）；将真实时间线和任务阶段接入此面板。
- P2：研究安全的、用户主动授权的 Obsidian 插件，聚合关系拓扑；不读取或展示正文；可即时断开。
- P3：事件可视化回放、筛选与原始事件证据跳转；避免误把可观测事件当隐藏推理。

本轮未执行远端部署或发布；线上 Pages 在新提交合并并完成部署之前仍是旧版。
