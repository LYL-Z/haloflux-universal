## 1. F-01 长会话回放分页

### 实现

`apps/companion/renderer/replay-history.mjs`：

- 以首次查询的 `to = Date.now()` 作为**稳定快照边界**，后续分页都带同一个 `to`，避免分页期间新写入事件造成重复/遗漏；
- 每页最多 1000（后端硬上限），按 `offset` 连续拉取，直到 `loaded >= total` 或达到 `maxEvents=20000`；
- 以 `eventId` 去重，最终按 `timestamp + eventId` 稳定排序；
- 返回 `{events,total,loaded,pages,partial,snapshotTo}`；
- UI 顶部显示 `loaded/total EVENTS`；达到上限或后端总数更大时显示 **PARTIAL REPLAY**。

### 验证

- 纯函数测试：
  - 2500 条 → 3 页、全部加载、无重复；
  - 5000 条 + `maxEvents=2000` → 2000 条、`partial=true`；
  - 快照边界：只请求 `to=1234`，不再读取后写入的事件。
- 真实 UI：临时写入 2500 条 generic 事件（session `replay-page-test`）→ `screenshots/p3/replay-paged-1600x900.png` 显示 **2500/2500 EVENTS**，3 页自动加载；测试后已 `history --delete-session` 删除。
- 既有 1000/2000 场景由 store 分页测试覆盖（`event-store.test.mjs` 1205 条，`limit=1000` + `offset=1000` 返回 205）。

## 2. F-02 `at` 参数

`parseReplayAt()` 明确区分：

| 输入 | 行为 |
|---|---|
| 无 `at` | `present=false` → 正常自动播放 |
| `at=0` | `present=true, valid=true, value=0` → 定位第一帧并暂停 |
| `at=42` | 定位第 42 个事件并暂停 |
| `at=abc` / `at=-1` / `at=1.5` / 空串 | `valid=false` → toast 提示，回退自动播放 |

单测：`tests/unit/replay-history.test.mjs` 覆盖上述 7 种输入。

## 3. F-03 持久性、安全与版本口径

### 重启前后内容一致性

- 重启前 2699 条；重启后 2705 条（新增 6 条）；
- 2699 个旧 `eventId` 全部存在：**missing=0、mismatch=0**（逐条 payload SHA256 比对）；
- 证据：`tests/evidence/p3/history-hashmap-before.json`、`history-restart-hash-check.json`。

### WAL / 断电

- `synchronous=NORMAL`：进程崩溃/异常退出安全；**系统断电或 OS 崩溃可能丢失最近已提交事务**。
- 不把 P3.2-A 描述为“绝对断电持久化”；需要更强保证应改 `synchronous=FULL`（本项目未启用，以避免写延迟）。

### Node 版本

- `node:sqlite` 从 **Node 22.13** 起无需实验标志；
- 根 `package.json` 与 `packages/event-store/package.json` 的 `engines` 已改为 `>=22.13.0`；
- 更老 Node 上 bridge 捕获初始化失败并降级为不持久化（不阻塞事件链）。

### 安全删除 / 访问控制

- `secure_delete=ON + DELETE + VACUUM` 只清理 SQLite 文件；**SSD 磨损均衡、文件系统快照、系统/云备份不在保证范围**。
- `/v1/history` 与 `/v1/state` 同级 Bearer 鉴权；数据库位于当前用户 `%LOCALAPPDATA%`，未加密，依赖 Windows ACL；token 文件仍是 P6 的 PARTIAL（0666）。
- 导出：`history --export` 只输出 schema 校验后的脱敏事件；热复制数据库可能不一致，建议停止 bridge 或使用备份 API。

### 写入负载

`tests/evidence/p4/store-bench.json`（临时 HOME，3000 条）：

- append p50 **0.050 ms**、p95 **0.097 ms**、p99 **1.776 ms**、max 6.73 ms；
- 总 318 ms，约 **9428 events/s**；
- 分块写入期间 event-loop delay mean 15.47 ms / p95 19.19 ms（受 timer 粒度影响，仅压力参考）；
- `integrity=ok`。
