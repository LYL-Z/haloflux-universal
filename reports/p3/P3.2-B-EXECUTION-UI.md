# P3.2-B · 执行链可视化（Tool Waterfall / DAG / Critical Path）

- 实现：`apps/companion/renderer/app.js`（TRACE 面板）、`packages/analytics`
- 结论：**PARTIAL**。Waterfall/DAG/Critical Path 的 UI 与证据追溯已接入；但当前 DSH 工具事件没有 `toolCallId`/`spanId`，所以真实数据只能显示 `HOST_REPORTED` 或 `UNCORRELATED`，DAG 明确降级为 Timeline，Critical Path 为 `UNKNOWN`。

## 1. 交互

- 顶栏 `TRACE` 打开研究面板；三个 tab：
  - **TOOL WATERFALL**：每条工具结束事件一行，含时间、工具、状态、耗时、source、Event ID；点击行打开 Evidence Inspector（Event ID、Session、Run、ToolCall、Source/Confidence、Duration、限制）。
  - **EXECUTION DAG**：只有 `parentSpanId` 能匹配到已观测 `spanId` 时才画边；否则显示 `NO TRUSTED DEPENDENCY EDGES · TIMELINE ONLY` 并列出时间线事件，不生成假因果边。
  - **CRITICAL PATH**：只有存在显式 `task.dependsOn` 数据时才计算；当前显示 `UNKNOWN · no trusted task dependency graph`，并展示公式。
- 回放模式下 TRACE 与 REPLAY 同步：每条行可追溯到 Event Store 中的真实 `eventId`。

## 2. 真实数据表现（DSH）

真实 `tool.end` 元数据没有 `toolCallId`：

```json
{"toolName":"edit","toolCategory":"file","toolStatus":"ok","turn":14,"step":70,"durationMs":27}
```

因此 Waterfall 显示：

- `HOST_REPORTED`：宿主给了 `durationMs`，但没有可匹配的 start/call ID；
- `UNCORRELATED`：没有耗时也没有匹配关系；
- 不会因为 `toolName` 相同或时间相邻就声称 `MATCHED`。

`toolWaterfall()` 的配对键严格为 `sessionId + runId + toolCallId`；缺失时不做配对。解析 `metadata.durationMs` 作为宿主报告值，并单独标注证据类别。

## 4. 限制（明确）

| 项 | 状态 | 原因 |
|---|---|---|
| Tool Waterfall 真实配对 | PARTIAL | DSH 当前不提供 `toolCallId`；只能显示宿主报告耗时 |
| Execution DAG | PARTIAL（Timeline 降级） | 没有 `spanId/parentSpanId`，不伪造边 |
| Critical Path | UNKNOWN | 没有任务 `dependsOn` 数据；公式已实现，数据缺失 |
| Agent/Run 关联 | PARTIAL | 有 session/run 指标；Agent 级 DAG 无数据 |
| 从画布到 Event ID | PASS | 行 title/Inspector 均含真实 eventId；回放来自 Event Store |

## 5. 结论

**P3.2-B = PARTIAL**。UI 与证据链可用，且在数据不足时明确降级；不能把当前 Waterfall 描述成“真实工具配对完成”，因为 DSH 没有 call ID。要转为 PASS，需要宿主提供稳定 `toolCallId`（已实现字段透传）与任务依赖/span 数据。
