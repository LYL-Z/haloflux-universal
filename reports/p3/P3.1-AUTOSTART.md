# P3.1 · Windows 自动启动与进程管理

- 分支：`feat/paper-lab-p2`
- 实现：`packages/service-manager/src/index.mjs`、`scripts/haloflux.mjs`
- 时间：2026-11-09T14:50–15:05Z
- 结论：**PASS（当前用户、无需管理员）**；重启电脑验证 **NOT_TESTED（需用户批准）**；DSH 宿主自动启动 **NOT_IMPLEMENTED（无官方安全接口）**。

## 1. 架构

两层：

1. **HALOFLUX 后台服务**：Task Scheduler 当前用户 `AtLogOn`（延迟 15 s）→ `haloflux supervise` → bridge + collectors + health monitor + 单实例锁 + 审计日志。Companion 窗口默认不自动打开（避免每次登录弹窗）。
2. **Agent 宿主**：只做发现/检测（进程、配置、bridge 连接、原生事件）；不伪造启动参数、不绕过 DSH 生命周期。DSH 由用户正常启动。

进程状态机：

`NOT_INSTALLED → INSTALLED → STARTING → HEALTHY → DEGRADED → STOPPING → STOPPED`，独立 `FAILED`；每次转换写 `%LOCALAPPDATA%\HALOFLUX\logs\supervisor.jsonl`。

## 2. 新增命令

```powershell
node scripts/haloflux.mjs autostart install
node scripts/haloflux.mjs autostart status [--json]
node scripts/haloflux.mjs autostart enable
node scripts/haloflux.mjs autostart disable
node scripts/haloflux.mjs autostart uninstall
node scripts/haloflux.mjs supervise [--once] [--duration 秒]
node scripts/haloflux.mjs doctor --startup
```

任务名：`HALOFLUX-Supervisor`；动作：当前 `node.exe` + 绝对脚本路径 + `supervise`；工作目录 `D:\HALOFLUX`；主体：当前用户、`Interactive`、`Limited`；`MultipleInstances=IgnoreNew`；无 SYSTEM/管理员。

## 3. 实测证据（本机 Windows 11）

| 操作 | 结果 |
|---|---|
| `autostart install` | `{"installed":true,"state":"Ready","enabled":true}` |
| 手动 `Start-ScheduledTask` | Task State=Running；`supervisor.json` → `HEALTHY`；bridge 被拉起 |
| `autostart disable` | State=Disabled，`enabled=false` |
| `autostart enable` | State=Ready，`enabled=true` |
| `autostart uninstall` | 任务删除；status `installed=false` |
| 重新 install | Ready；再次 start → supervisor `HEALTHY` |
| `stop`（用户主动） | 写 `supervisor.stop`，supervisor **graceful** 退出，bridge/collectors 停止，锁释放 |
| 单实例锁 | 第二次 `supervise` 返回 `already-running`，不产生第二份 bridge |
| 退避 | 健康检查失败 → DEGRADED → STARTING；`backoff = min(30s, 1s×2^n)`，最多 5 次后 FAILED 冷却 |
| 日志 | `logs/supervisor.jsonl`（状态转换）；`logs/bridge.log`；无 token |

证据文件：`tests/evidence/p3/autostart-status.json`、`task-scheduler.txt`、`supervisor-state.json`、`supervisor-events.jsonl`、`doctor-startup.txt`。

## 4. 启动顺序（重要）

DSH 的 bridge 插件在 DSH 启动时连接 bridge；若 bridge 未运行，当前实现不会补发历史事件（审计 A8）。因此：

1. 登录后 supervisor 自动启动 bridge；
2. 再打开 DeepSeek Harness；
3. 打开 companion（`haloflux companion`）即可看到 `NAT` 事件。

若先开 DSH 后开 bridge，需要重启一次 DSH（或后续实现插件重连）。
