# P3.2-C · 模型可观测能力矩阵

- 调查对象：DeepSeek Harness 0.2.1-rc.5（本机）、`dsh-haloflux-bridge`、DeepSeek 官方 API 公开能力
- 结论：**模型请求生命周期/TTFT/Token usage/Reasoning 在本机当前接入路径中 NOT_IMPLEMENTED**；不伪造、不劫持。
- 日期：2026-11-09

## 1. 现状证据

DSH adapter 只订阅宿主的 session 事件：

```js
session/created, session/event, session/disposed, agent/error
```

映射到 HALOFLUX 的事件仅包括 `session.*`、`run.*`、`task.received`、`tool.*`、`output.*`、`approval.*`、`error`。没有 model request / first-token / usage / reasoning 事件。

真实 `/v1/history` 的 `tool.end` 元数据只有：

```json
{"toolName":"edit","toolCategory":"file","toolStatus":"ok","turn":14,"step":70,"durationMs":27}
```

没有 `toolCallId`、`traceId`、`modelRequestId`、`ttftMs`、`promptTokens`、`completionTokens`、`reasoningTokens`。

## 2. 能力矩阵

| 数据 | 当前可得 | 证据 | 处理 |
|---|---|---|---|
| 模型名 | 有时（session metrics） | `/v1/state.metrics.model` | 显示；缺失 `—` |
| 请求开始/结束 | **不可得** | 无事件 | `UNKNOWN`，不估算 |
| TTFT | **不可得** | 无 first-token 事件 | `UNKNOWN` |
| 输出 Token 数 | 部分（会话 metrics） | `tokenCount/tokensPerSecond` | 仅在宿主提供时显示 |
| 输入/缓存/Reasoning Token | **不可得** | 无 usage 字段 | `UNKNOWN` |
| Finish reason / HTTP 错误 | 部分（error 事件） | `error.errorCode` | 仅显示已观测错误 |
| `reasoning_content` | **不可得** | DSH adapter 未暴露 | 不读取、不保存、不显示 |
| 工具参数/结果 | 禁止 | schema allowlist | 永不采集 |

## 3. 可执行方案（需宿主支持，不由监控层注入）

1. **官方 LLM middleware/hook**：由 DSH 提供请求/响应事件（request id、start、first chunk、usage、finish reason）；adapter 只订阅，不改写请求/响应。
2. **Provider 直连模式**（可选、默认关闭）：若用户自己的 API adapter 暴露 `usage`/`reasoning_content`，通过独立授权开关采集；默认不持久化推理文本，只存统计元数据。
3. **不采用**：代理劫持 HTTPS、修改 DSH 模型调用、抓包读取正文、用工具耗时推算模型耗时。

## 4. 对 UI 的约束

- 模型面板在无数据时显示 `UNKNOWN` / `WAITING FOR PROVIDER EVENT`；
- 不画“思考中”假动画，不以随机数填充 token/TTFT；
- 若将来接入 reasoning，必须标 `PROVIDER-EXPOSED REASONING`，默认关闭、仅当前会话、不写入 Event Store/截图/回放。

## 5. 结论

**P3.2-C = NOT_IMPLEMENTED（能力缺口）**。当前只能真实观测会话、工具、输出和错误；模型请求级数据需要 DSH 官方事件接口。下一步应先向 DSH 确认可用 hook/telemetry，再实现，否则只能保持 UNKNOWN。
