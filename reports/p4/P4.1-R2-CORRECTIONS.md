## 1. F-06 不可变入库序列

`packages/event-store/src/index.mjs`：

- 持久化 `meta.seq_highwater`（数据库内 high-water mark），每次写入在 `BEGIN IMMEDIATE` 事务中：
  1. 读 highwater；
  2. `seq = highwater + 1`；
  3. 更新 highwater；
  4. `INSERT OR IGNORE` 事件；
  5. COMMIT。
- `append()` 与 `appendMany()` 使用同一事务边界；`appendMany` 不嵌套 `BEGIN`。
- 删除事件/会话、`VACUUM`、关闭重开、进程崩溃后恢复都不会降低 highwater；重复 eventId 幂等。
- 旧库迁移：`ALTER TABLE ADD seq` → backfill `rowid` → 创建唯一索引 → highwater = max(seq)；payload/eventId/timestamp/source 全部保留。
- 快照仍是 `snapshotSeq + afterSeq` 游标；旧快照看不到新 seq。

测试（`tests/unit/event-store.test.mjs`）：

- 删除最大 seq 后插入 → 新 seq 更大，旧快照不包含 D；
- 删除多个尾部、`VACUUM`、关闭重开、删除会话后插入；
- 多连接并发写；
- 旧 P3.2-A schema 迁移；

## 3. F-08/F-09 代码修复

- **单次排序**：`collectReplayPages` 不再排序；`startReplay` 不再 `sortEvents`；`prepareReplay` 只排序一次。
- **最小更新**：新增 `renderReplayFrame()`，只更新 `renderSession/renderEvents/renderMode/renderCompact/renderLabMonitor`；`applyReplayFrame(index,{full:true})` 仅首帧/seek 全量。
- **增量事件前缀**：回放前进时只 push 新可见事件；不再每帧 `slice(0,index+1)`。
- **Projection 窗口**：回放时只对最近 200 条事件做投影，计数用 prepared 前缀计数器，保留真实总量。
- **Canvas backing store**：`canvasContext` 仅在 CSS 尺寸/DPR 变化时设置 width/height。
- **时间带密度**：1024 桶聚合；回放时不再逐事件绘制。
- **TRACE 行数**：Waterfall 最多渲染最近 300 行，明确标注 `SHOWING LAST 300/N ROWS · FULL DATA REMAINS IN EVENT STORE`。
- **单调时钟**：回放使用 `performance.now()` anchor + elapsedBase，暂停/恢复/倍速/拖动不会累积 200ms 漂移。
- **旧 v1/v2 数据库兼容**：迁移保留 payload。
