## 3. Token Telemetry

### Source audit

DSH bridge `assistant/message` → `output.end` metadata:

- `tokenCount = usage.outputTokens` (per assistant message)
- `contextUsed = sumUsageInput(usage)`
- `contextLimit`, `model`

Other observations:

- `run.end` `tokenCount` = turn total.
- heartbeat `tokenCount` = cumulative context snapshot in observed history.
- `inputTokens`, `cacheRead/cacheWriteTokens` are **not forwarded** into HALOFLUX metadata.
- No `requestId`, TTFT, reasoning token usage, tokensPerSecond, or hidden reasoning text.

### Implementation

`apps/companion/renderer/token-telemetry.mjs`:

- sums tokenCount **only for `output.end`**;
- does not sum run.end or heartbeat tokenCount;
- contextUsed/contextLimit from explicit metadata, fallback to selected session host metrics;
- dedupes eventId;
- simulated sources remain flagged;
- input/cache/reasoning/TTFT/requestId/tokensPerSecond are **UNAVAILABLE**, not 0;
- no token derivation from event/tool/text counts.

Tests: `tests/unit/token-telemetry.test.mjs` 6 tests.

Real DSH screenshot: `p43-live-real-100-final.png` shows `TOKEN TELEMETRY · HOST-REPORTED` with OUTPUT/INPUT/CACHED = UNAVAILABLE, because the current live window has no `output.end` tokenCount. Context may fall back to session metrics when present; no fabricated number.
