# P4.2-D · Right Event Beams

- Status: **PARTIAL**
- Module: `apps/companion/renderer/event-beams.mjs`, overlay in `app.js`
- Baseline: `829f34d`

## Implementation

- Observed `tool.start` → outward beam; `tool.end` → inward beam; `tool.fail`/`error` → fail beam; `tool.retry` if present → dashed retry beam.
- `eventId` is required; missing ID cannot create a pulse.
- Source/confidence changes opacity/dash only, never status/facts.
- Ingestion is eventId-idempotent, rate-limited (40ms) and capped (36 active; 8 drawn).
- Replay pauses drawing when paused; reduced-motion disables animation.
- There is no mapping for model request/TTFT/reasoning because those are not HALOFLUX event types.

## Tests

`tests/unit/event-beams.test.mjs` (4 tests): type mapping, missing eventId rejection, idempotence/cap, decay, high-frequency limit, model/reasoning never create beams.

## Why PARTIAL

The beam code is real and evidence-bound, but at current opacity/geometry the pulses are too subtle in the dense field: only a `START` label is clearly readable and multiple simultaneous lanes are hard to distinguish. Fail/retry rhythm has unit coverage but no real fail/retry event was observed in the current DSH session, so the visual behavior is not proven on real host data.

No fake pulse is added to compensate.
