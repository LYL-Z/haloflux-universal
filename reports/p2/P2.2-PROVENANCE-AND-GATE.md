## 2. 事件级 provenance（本轮核心修复）

### 2.1 四层链路

| 层 | 文件 | 修改 |
|---|---|---|
| 状态机 | `packages/session-manager/src/index.mjs` | `recentEvents` 每条写入 `source`/`confidence`（及 `runId`），不再只存类型/时间/工具 |
| 归一化 | `packages/visual-core/src/state-map.js` | `normalizeSession` 保留 `source/confidence/toolCallId/durationMs/errorCode/runId`，此前这些字段在渲染前被裁掉 |
| 渲染器 | `apps/companion/renderer/app.js` | `ingestEvents` 使用 `event.source/confidence`；缺失时写 `unknown`，**禁止**回退到 `session.source` |
| 投影/UI | `monitor-projection.mjs` + app.js | 时间线显示每条事件的 `NAT/DRV/SIM/UNK`；详情条显示该事件的 source/confidence |

## 3. Failure Trace 时间窗修复

- 旧事件不再压到画布左边界：先按 `timestamp >= now - 120s` 过滤，窗口外事件不参与绘制；
- 空窗口显示 `NO FAILURE EVENTS IN 120 S (NOT A PASS)`；
- 明确 `120s WINDOW · N CACHED`（VALIDATION 单元 OBSERVATION 行）；
- “没有错误 ≠ 验证通过”：PASS/FAIL 保持 `— / —`。

## 4. Tool Event Rate 口径

- 文案：`RATE 120s · 10s BUCKET · N CACHED (NOT TOTAL)`；
- 统计对象是**选中会话的缓存事件**（渲染器最多保留 30 条），不是完整历史调用次数；
- 空窗口显示 `NO TOOL EVENTS IN 120 S WINDOW`，不画随机波形。

## 5. 关联边角：重复 ID / 乱序 / 跨 run

| 场景 | 行为 | 测试 |
|---|---|---|
| 同一会话重复 `tool.start`（同 ID） | 保留最早时钟，不重置耗时 | duplicate start → 1000 ms（不是 500） |
| `tool.end` 早于 `tool.start` | 判为乱序，`UNCORRELATED`，不产生 0/负耗时 | out-of-order test |
| 跨 run 复用同一 `toolCallId` | 关联键为 `runId + callId`；run-A 的 end 不会匹配 run-B 的 start | cross-run test |
| 孤立 `tool.end` + `toolCallId` | `UNCORRELATED`、耗时 `—` | P0.1 regression B |

## 6. 性能复测（新增画布后）

- 可见窗口 1600×900（实际内容 1536×900，DPR 2.5，GPU 报告 `software` 合成，口径同 P6）：
  - 12 s rAF 采样：**38.57 fps**，frame mean **25.93 ms**，p95 **45.80 ms**，max 91.70 ms，heap 12.3 MB。
- overlay 模式：**28.49 fps**，mean 35.10 ms，p95 41.80 ms。
- compact 320×320：rAF 采样异常（207 fps，无 vsync），**不采信**；不写入结论。
- 30 min soak（隔离端口、无 renderer）：**PASS**。1800 s / 359 samples；发送 **11631/11631 accepted**；bridge RSS **62.21 → 74.86 MB（+12.65）**；CPU mean 0.02% / max 0.09%；12 sessions（`tests/evidence/p2-perf/soak-30min-p22.json`）。
- 与 P6 的 31/24/24 口径不同（屏幕/DPR/可见性不同），不可直接相减；只作为“新增画布后未出现数量级回退”的证据。
